# 검과 방패 — 작업 계획서

- 파일: `games/sword_and_shield.html` (단독 실행 가능)
- 게임 id: `sword_and_shield`
- 저장 키: `recreation:sword_and_shield:state`(진행 중 상태), `recreation:sword_and_shield:saved`(이어하기용 보관 게임)
- 진행 방식: 심판이 PC 한 대를 들고 진행. 플레이어는 리더 확인·무기 장착 때만 화면을 본다. PIN 없음.
- 상태: **1차 구현 완료**. 규칙 해석 확정(7장), 인원별 무기 수 확정(5장).

## 1. 게임 규칙 (원문 정리)

1. 플레이어는 드래프트로 같은 인원의 **Verita** 팀과 **Falso** 팀으로 나뉜다. 원문은 10명(5:5)이며, 이 도구는 6~20명(3:3~10:10)을 지원한다(5장).
2. 팀마다 제비뽑기로 리더 1명. 리더가 누구인지는 같은 팀원에게도 공개하지 않는다.
3. 팀마다 무기를 받아 1명당 2개씩 나눈다. 5:5 기준 검 4, 쌍검 1, 방패 3, 맨손 2(인원별 수는 5장).
   - 검: 상대 1명에게 피해 1.
   - 쌍검: 상대 1명에게 피해 2.
   - 방패: 피해를 3번까지 막는다. 3번을 다 쓰면 소멸한다.
   - 맨손: 공격·방어 능력 없음.
4. 각자 2개를 왼쪽/오른쪽에 비공개로 장착한다. 위치는 바꿀 수 없다.
5. 팀 내 공격 순서를 정하고, 동전 던지기로 선공 팀을 정한다. 양 팀이 번갈아 공격한다.
6. 공격: "왼쪽 검으로 OO씨를 공격하겠습니다"처럼 **팔과 무기를 선언만** 한다. 실제 무기는 공개하지 않는다.
7. 방어: 공격받은 사람도 무기를 공개하지 않고 선언으로 방어한다. 즉 공격·방어 모두 거짓일 수 있다.
8. 방어하지 못하면 즉시 사망. 사망자는 이후 공격에서 빠지고, 무기는 공개되지 않는다.
9. 자기 차례에 '패스'할 수 있다. 횟수 제한 없음.
10. 의심
    - **살아 있는 플레이어**는 누구나(공격·방어 당사자가 아니어도) **직전에 선언된 무기**에 대해서만 의심할 수 있다.
    - 의심받은 사람은 그 무기를 공개한다.
    - 불일치: 선언한 능력은 무효, 의심받은 사람 사망.
    - 일치: 선언한 능력은 유효, 의심한 사람 사망.
11. 모든 생존자가 한 번씩 공격하면 라운드 종료. 다음 라운드는 선·후공이 바뀐다.
12. 한 팀의 **리더가 사망하는 즉시** 게임 종료. 리더가 죽은 팀이 패배.
13. 인원이 줄면 다음 순서가 당겨진다.
    - 예) Falso 선공, Falso③ 사망: F① → V① → F② → V② → F④ → V③ → F⑤ → V④ → V⑤
14. 팀 게임으로 진행한다. 리더를 먼저 잃지 않은 팀이 승리하면 끝이다. 원문의 보상·탈락 규칙(가넷, 생명의 징표, 블랙 가넷, 탈락 후보, 데스매치)은 쓰지 않는다.

## 3. 화면 흐름

```
설정(명단·팀) ──▶ 게임 준비 ──▶ 진행 ──▶ 결과
                  ├ 1. 리더 확인(모달)
                  ├ 2. 무기 장착(모달)
                  ├ 3. 공격 순서
                  └ 4. 선공 팀
```

- 리더 확인·무기 장착·순서·선공은 한 화면('게임 준비')에 모았다. 순서와 상관없이 처리할 수 있고, 전부 끝나야 '게임 시작'이 켜진다.

- 뒤로가기·이어하기는 좀비 게임과 같다. 설정 화면에서는 게임 목록, 그 외 화면에서는 설정 화면으로 가며 진행 중 게임은 `saved`에 보관.

### 3.1 설정

- 이름 입력 → 카드 추가(좀비 게임과 같은 입력 방식, 한글 조합 중 Enter 무시, 중복 불가).
- 이름 카드를 눌러 팀 지정(Verita / Falso / 미지정). 드래프트는 구두로 진행하고 결과만 입력.
- 시작 조건: 두 팀 인원이 같고, 팀당 3~10명.
- 팀 인원에 맞는 무기 구성(5장 표)을 설정 화면에 표시.

### 3.2 리더 확인 (모달)

- 게임 준비 화면에 들어가면 팀별로 무작위 1명을 리더로 뽑는다. '다시 뽑기' 가능(확인한 사람이 있으면 확인 후).
- 이름을 누르면 바로 본인 화면(리더 여부)이 열리고, 연 것으로 확인 처리 → 가리기. 중간 안내 화면("OO님에게만 보여주세요")은 두지 않는다.
  - 표시 내용: "당신은 Verita 팀 **리더**입니다" / "리더가 아닙니다".
- 미확인자가 있으면 게임 시작 때 확인을 묻는다.

### 3.3 무기 장착 (모달)

- 플레이어별 비공개 입력: 이름을 누르면 바로 왼손·오른손 무기 선택 화면이 열린다.
- 팀 재고(5장 표)를 넘는 선택은 막는다. 남은 재고를 표시.
- 팀원이 모두 입력해야 다음 단계로. 입력 후에는 가려지고, 다시 열면 수정 가능(게임 시작 전까지만).

### 3.4 공격 순서·선공

- 팀별로 ①~ⓝ 순서 지정(카드를 눌러 순서대로 번호 부여, 다시 누르면 해제하고 뒤 번호를 당김). 무작위·초기화 버튼.
- 선공 팀: 동전 던지기 버튼(무작위) 또는 직접 선택.

### 3.5 진행

- 상단 패널: 라운드, 이번 라운드 선공 팀, **현재 공격자**, 양 팀 생존자 수.
- 양 팀 플레이어 카드(공격 순서대로). 사망자는 흐리게, 이번 라운드 공격 완료자는 표시.
- 심판용 정보(실제 무기, 방패 남은 횟수, 리더 표시)는 **정체 숨기기 토글**로 가린다. 화면을 플레이어에게 보여줄 때를 대비해 기본은 숨김.
- 한 턴의 단계(버튼으로 진행):
  1. 공격자 행동: **공격 선언**(팔 왼/오, 무기 검/쌍검, 대상) 또는 **패스**.
  2. 공격 의심 창: "의심 없음" 또는 의심한 사람(생존자만) 선택 → 도구가 실제 무기 공개·판정.
     - 공격이 거짓이면 공격자 사망, 공격 무효 → 턴 종료.
     - 공격이 참이면 의심한 사람 사망, 공격 계속. 의심한 사람이 대상 본인이었다면 방어 단계 생략.
  3. 방어 선언: 팔 왼/오 + 방패, 또는 "방어 안 함".
     - 그 팔의 방패 선언 누적 피해 + 이번 피해가 3을 넘으면 선택할 수 없다(진짜·거짓 방패 모두, 7장 1·2).
  4. 방어 의심 창: 위와 같은 방식으로 판정.
  5. 결과 반영: 피해가 방어되지 않으면 대상 사망.
- 매 사망 직후 리더 여부를 확인해, 리더면 즉시 결과 화면으로.
- **되돌리기**: 마지막 입력 1단계를 취소(잘못 누른 경우). 이벤트 순서에 결과가 의존하므로 중간 기록 삭제는 두지 않는다.
- 하단 기록 표: R | 진행(공격 선언·의심·방어를 한 칸에 줄바꿈으로) | 사망.
- 플레이어 카드에는 팔별 선언 이력(공개 정보)과 방패 선언 누적(예: 🛡️ 2/3)을 표시. 심판 정보를 켜면 실제 무기와 👑 리더도 표시.
- 맞지 않는 단계의 입력(늦게 눌린 버튼 등), 사망자·선언자 본인의 의심은 기록하지 않는다.
- 같은 팔에 이전과 다른 무기를 선언하면 심판 화면에만 경고 표시(처리는 의심에 맡김).

### 3.6 결과

- 승리 팀, 사망한 리더, 사망 경위.
- 전원의 팀·리더 여부·실제 무기 공개 표.
- 전체 기록 표, 같은 명단으로 새 게임 / 전체 초기화.

## 4. 데이터 설계

### 4.1 상태 (`S`)

```js
{
  phase: 'setup' | 'prep' | 'playing' | 'final',
  roster: [{ name, team: 'V' | 'F' | null }],
  players: [{ name, team: 'V' | 'F' | null, leader, checked, L, R, order }],
  //   L, R: 'sword' | 'dual' | 'shield' | 'bare'
  firstTeam: 'V' | 'F',      // 1라운드 선공
  reveal, events: []
}
```

### 4.2 이벤트 소싱

좀비 게임과 같이 이벤트만 저장하고 `compute()`가 처음부터 재생한다.

- 공격: `{ type:'attack', arm:'L'|'R', claim:'sword'|'dual', target }`
- 패스: `{ type:'pass' }`
- 의심: `{ type:'doubt', by }` / 의심 없음: `{ type:'nodoubt' }` (직전 선언에 대한 것. 판정은 재생 때 계산)
- 방어: `{ type:'defend', arm: 'L'|'R'|null }`  (`null` = 방어 안 함)
- 공격자·방어자는 재생 중 현재 차례로 정해지므로 이벤트에 넣지 않는다. 되돌리기는 마지막 이벤트를 빼는 것.

`compute()`가 만드는 것: 생존 여부, 팔별 방패 선언 누적 피해, 라운드·현재 공격자·현재 단계, 사망 경위, 최초 의심 성공자, 종료 여부.

### 4.3 공격 순서 계산

- 라운드마다 선공 팀이 바뀐다.
- 다음 공격자 = 직전 공격자의 **상대 팀**에서 이번 라운드에 아직 공격하지 않은 생존자 중 순서가 가장 빠른 사람. 없으면 같은 팀에서 고른다. 둘 다 없으면 라운드 종료.
- 위 예시(F③ 사망 → F①V①F②V②F④V③F⑤V④V⑤)와 일치하고, 라운드 도중 사망에도 그대로 적용된다.

### 4.4 판정

- 공격 효과: 검 1, 쌍검 2의 피해. 방어하지 못하면 피해량과 관계없이 사망.
- 방어 효과: 선언한 팔의 방패 횟수에서 피해만큼 차감. 쌍검은 2회분을 쓴다. 남은 횟수가 피해보다 적으면 그 팔로는 방어 선언 불가.
- 방패 횟수는 **선언 기준**으로 센다. 실제 방패든 거짓 방패든 팔마다 누적 3까지이며, 다 쓰면 소멸(그 팔로 더는 방패 선언 불가).
- 의심 판정: 선언한 무기와 해당 팔의 실제 무기를 비교(검 ≠ 쌍검).
- 의심은 직전 선언(공격 또는 방어)에만, 생존자 1명만 한다.

## 5. 인원별 무기 수

### 5.1 표 (팀당)

| 3 (6명) | 2 | 1 | 2 | 1 | 44.7% | 2.18 | 37.9% |
| 4 (8명) | 3 | 1 | 2 | 2 | 46.1% | 1.89 | 36.5% |
| **5 (10명)** | **4** | **1** | **3** | **2** | **46.6%** | **2.18** | **36.2%** |
| 6 (12명) | 4 | 2 | 4 | 2 | 46.4% | 2.20 | 35.7% |
| 7 (14명) | 5 | 2 | 4 | 3 | 47.6% | 2.05 | 35.4% |

- 5:5는 원문 구성 그대로(기준).
- 최소 3:3, 최대 10:10으로 고정. 두 팀 인원이 다르면 시작할 수 없다(무기가 같아야 팀 간 조건이 대칭이 된다).

### 5.2 고르는 기준

- 두 팀은 같은 무기를 받으므로 무기 수로 팀 간 승률이 달라지지 않는다. 그래서 목표는 **원작(5:5)의 게임 감각 유지**로 잡았다.
  1. 평균 라운드 수(게임 길이)가 기준과 ±8% 이내.
  2. 사망 비율(끝날 때까지 죽는 인원 비율)이 기준과 ±6% 이내.
  3. 선공 승률이 기준보다 50%에서 더 멀어지지 않음(+1%p 여유).
- 위 조건을 만족하는 구성 중 원작 비율(4:1:3:2)에 가장 가까운 것을 고르고, 인원이 늘 때 어떤 무기도 줄지 않게 했다.
- 첫 탐색에서 점수 1위만 고르면 쌍검이 인원에 따라 1→3→1→3으로 오락가락했다. 상위 후보 간 차이가 표본 오차 수준이라, 위의 "허용 범위 + 원작 비율" 규칙으로 바꿨다.
- **3:3, 4:4는 허용 범위를 모두 만족하는 구성이 없었다.** 무기가 6~8개뿐이라 1개 차이로 게임 길이가 ±15% 이상 움직인다. 가장 가까운 구성을 넣었다.
  - 3:3 `2/1/2/1`: 선공 승률만 기준보다 0.1%p 벗어남.
  - 4:4 `3/1/2/2`: 게임이 약 13% 짧다. 대안 `3/1/3/1`은 약 13% 길다.

### 5.3 시뮬레이션 모델 (가정)

스크립트: `work/games/sim/sim.js`(게임 1판 시뮬레이션), `work/games/sim/pick.js`(인원별 구성 선택). `node work/games/sim/pick.js`로 재현.

- 팀 무기는 무작위로 분배(리더가 팀원에게도 비공개라 리더에게 몰아줄 수 없음).
- 공격: 진짜 쌍검 > 진짜 검 순으로 사용. 공격 무기가 없으면 확률 b로 '검' 허세 공격, 아니면 패스. 리더는 허세하지 않는다.
- 대상: 상대 생존자 중 무작위(리더를 모르므로).
- 방어: 진짜 방패 > 거짓 방패 > 방어 안 함. 선언 누적 3 제한 준수, 이미 다른 무기로 선언한 팔은 쓰지 않음.
- 의심: 공개 정보(팀 무기 수, 팔별 선언·공개 이력)로 거짓일 확률을 추정해 임계값 θ 이상이면 상대 팀 생존자 1명이 의심. 리더는 확실한 거짓일 때만 의심.
- 행동 변수 조합(b ∈ {0.3, 0.6}, θ ∈ {0.5, 0.7})을 모두 돌려 평균. 구성당 4.8만~8만 판.

### 5.4 한계

- 결과는 위 행동 모델에 대한 **상대 비교**다. 실제 사람의 허세·의심 빈도가 모델과 다르면 절대값(라운드 수 등)은 달라진다. 다만 인원 간 비교는 같은 모델이므로 비교적 안정적이다.
- 모든 인원에서 선공 승률이 45~48%로, **후공이 약간 유리**하다. 무기 수로는 고쳐지지 않는 구조적 특성(선공의 공격 선언이 먼저 노출됨)으로 보인다. 원문 규칙이 라운드마다 선·후공을 바꾸므로 그대로 둔다.
- 실제 진행 후 게임 길이가 크게 다르면 5.1 표를 다시 조정한다.

## 6. 구현 방침

- 좀비 게임의 구조(CSS 변수, 상태·저장·`toSetup`·이어하기, `data-act` 이벤트 위임, 개인 확인 모달)를 그대로 따른다.
- 공통 스타일 분리(`games/common.css`)는 하지 않는다. 각 게임 HTML을 단독 실행 가능하게 유지한다는 원칙(work.md 2장)이 우선이다.
- 팀 색: Verita 파랑 계열, Falso 빨강 계열(좀비 게임의 `--human`, `--zombie` 값 재사용).
- 무기 표는 HTML 안의 상수 `WEAPONS = { 3: [2,1,2,1], ..., 10: [8,2,6,4] }`(검·쌍검·방패·맨손)로 둔다.
- `games/games.js` 등록: `{ id: 'sword_and_shield', icon: '⚔️', title: '검과 방패', ... }`.

### 테스트

- Node 로직 테스트: 공격 순서 당김(원문 예시), 의심 성공/실패, 쌍검 vs 방패, 방패 누적 3 제한(진짜·거짓), 리더 사망 즉시 종료, 사망자 의심 불가, 되돌리기 후 재계산, 인원별 재고 검증.
- 헤드리스 Chrome: 설정 → 리더 확인 → 무기 장착 → 순서 → 한 게임 끝까지 클릭 흐름, 콘솔 오류·스크린샷 확인.

## 7. 규칙 해석 (확정)

1. **거짓 방패**도 팔마다 3회까지만 막을 수 있다. (확정)
2. **방패는 3회 쓰면 소멸**한다. 소멸한 팔로는 방패 선언 불가. 쌍검은 2회분으로 센다. (확정, 횟수 단위는 원문 "쌍검 = 2번의 피해"에 따름)
3. **패스 반복**은 제한하지 않는다. (확정)
4. **의심은 생존자만** 할 수 있다(원문 각주 [2]의 취지). (확정)
5. 같은 팔에 다른 무기 선언: 도구가 막지 않고 심판 화면에만 경고. 처리는 의심에 맡김.
6. 동시 의심: 심판이 먼저 외친 1명만 선택.
7. 대상 본인이 공격을 의심했다 실패해 사망하면 방어 단계 생략.
8. 드래프트 방식(원문 각주 [1])은 도구 밖에서 진행하고 팀 결과만 입력한다.
