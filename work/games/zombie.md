# 좀비 게임 — 작업 계획서

- 파일: `games/zombie.html` (단독 실행 가능)
- 저장 키: `recreation:zombie:state`(진행 중 상태), `recreation:zombie:saved`(이어하기용 보관 게임)
- 진행 방식: 심판이 PC 한 대를 들고 진행. 플레이어는 역할 확인 때만 화면을 본다. PIN 없음.

## 1. 게임 규칙

1. 3라운드, 라운드당 n분(기본 30분).
2. 공개된 장소에서 1:1 터치. 터치 결과는 알려주지 않는다.
3. 좀비–인간 터치 → 인간이 좀비가 된다. 같은 편끼리 터치하면 아무 일도 없다.
4. 라운드당 터치 횟수 제한은 없지만, 같은 두 사람은 게임 전체에서 한 번만 터치할 수 있다.
5. 한 라운드 동안 아무와도 터치하지 않은 인간은 라운드가 끝날 때 좀비가 된다.
6. 각 라운드가 끝나면 좀비 수와 인간 수를 공개한다.
7. 모든 플레이어는 치료제 1개를 가진다.
   - 감염된 같은 라운드 안에서, 감염 후 **라운드 시간의 1/3** 안에 쓰면 감염이 취소된다(30분 라운드면 10분).
   - 본인이 감염됐는지 모르는 상태로 쓴다. 감염되지 않았을 때 쓰면 그냥 소모된다.
8. 승리 판정
   - **라운드가 끝난 시점**에 인간이 0명이면 좀비 승리, 즉시 결과 화면으로 간다. 라운드 도중에는 판정하지 않는다.
   - 3라운드가 끝났을 때 인간이 1명 이상이면 인간 승리.

## 2. 화면 흐름

```
설정 ──역할 확인(모달)──┐
  │                      │
  └──게임 시작──▶ 라운드 진행 ──▶ 쉬는 시간 ──▶ (다음 라운드) ... ──▶ 최종 결과
                                                                     └─ 타임랩스(모달)
```

- 뒤로가기: 설정 화면에서는 게임 목록(`../index.html`), 그 외 화면에서는 설정 화면.
- 진행 중에 설정으로 나가면 시계를 멈추고 게임을 `saved`에 보관 → 설정 화면에 "이어하기" 카드가 뜬다.

### 2.1 설정

- 라운드 시간(분) 입력.
- 이름 입력 → Enter 또는 확인 버튼으로 카드 추가, 카드의 ×로 삭제. 한글 입력 중(`isComposing`) Enter는 무시. 중복 이름 불가.
- 인원 수는 이름 개수로 자동 표시.
- 좀비 수: 인원에 맞춰 추천값이 자동 적용되고, 직접 바꿀 수 있다. 추천값 옆에 예상 좀비 승률 표시.
- 하단 버튼: **역할 확인**, **게임 시작**.
  - 이름이나 좀비 수가 바뀌면 역할을 다시 배정한다(이미 확인한 사람이 있으면 확인 후 재배정).
  - 역할을 확인하지 않은 사람이 있으면 시작 전에 확인을 묻는다.

### 2.2 역할 확인 (모달)

- 이름 카드를 크게, 한 줄에 4명.
- 이름을 누르면 바로 역할이 보이고(연 것으로 확인 처리) → 가리기. 확인한 사람은 카드에 표시.
- 역할 배정은 Fisher–Yates 셔플(모든 사람이 좀비가 될 확률이 같음).

### 2.3 라운드 진행

- 상단 타이머 패널: 남은 시간, 실시간 좀비/인간 수. 패널 하단에 일시정지 · 정체 숨기기 · 라운드 종료.
- 타이머 아래 플레이어 카드(한 줄 4명). 두 명을 차례로 누르면 터치가 즉시 기록된다.
  - 이번 라운드에 아직 터치하지 않은 사람은 빨간색.
  - 심판용으로 좀비 표시(정체 숨기기 토글로 가릴 수 있음).
  - 이미 터치한 쌍은 다시 기록할 수 없다.
- 하단 기록 표(컬럼): 시각 | 플레이어 | 상대 | 결과 | 치료 가능 | ×
  - ×로 해당 기록 삭제(확인 후, 연결된 치료제 기록도 함께 삭제).
  - 이름 옆 치료제 버튼 → 확인 후 사용. 남은 사용 가능 시간을 표시하고, 지나면 비활성화. 잘못 누른 사용은 취소 가능.
- 시간이 다 되면 자동으로 라운드 종료.

### 2.4 쉬는 시간

- 라운드 진행 화면과 같은 패널 형태로 좀비/인간 수 표시.
- 접촉 현황 표: 플레이어 | 상태 | 횟수 | 접촉한 상대.
- 해당 라운드 기록 표. 미접촉으로 좀비가 된 사람도 기록에 표시.

### 2.5 최종 결과

- 승리 측, 통계.
- 최종 상태 표, 라운드별 기록 표(진행 화면과 같은 UI).
- 플레이어별 타임라인 필터.
- **타임라인으로 보기**: SVG 원형 배치로 터치·감염·치료·라운드 종료를 한 단계씩 재생.
  - 재생/일시정지, 이전/다음, 슬라이더, 속도 선택. 키보드: Space, ←/→, Esc.
- 같은 멤버로 새 게임 / 전체 초기화.

## 3. 데이터 설계

### 3.1 상태 (`S`)

```js
{
  phase: 'setup' | 'playing' | 'break' | 'final',
  roundMinutes, names: [], zombieCount /* null = 자동 */,
  players: [{ name, zombie0, checked }],
  round, endedRounds,
  clock: { startedAt, pausedAt, pausedTotal },
  seq, reveal, events: []
}
```

### 3.2 이벤트 소싱

- 저장하는 것은 이벤트뿐이다.
  - 터치: `{ id, type:'touch', round, t, a, b }`
  - 치료제: `{ id, type:'cure', round, t, p, touch }`
- `compute()`가 이벤트를 처음부터 재생해 현재 상태와 타임라인을 만든다.
  - 타임라인 항목: 터치(감염자/감염시킨 사람), 치료(효과 있음/없음), 라운드 종료 시 미접촉 좀비화(auto).
- 덕분에 기록 하나를 지워도 이후 결과가 자동으로 다시 계산된다.
- 시간 `t`는 일시정지 시간을 뺀 게임 시간(`elapsed()`).

## 4. 밸런스 (좀비 수 추천)

- 가정: 모두 라운드당 1회, 아직 안 만난 상대와 무작위로 터치(좀비도 인간인 척 1회만 터치).
- 인원 6~60명은 몬테카를로 시뮬레이션 결과표(`WIN_RATE`)에서 좀비 승률이 50%에 가장 가까운 좀비 수를 고른다.
- 표 밖(61명 이상)은 `max(1, round(0.4n − 3))`.

| 인원 | 추천 좀비 | 예상 좀비 승률 |
| --- | --- | --- |
| 8 | 1 | 52% |
| 10 | 2 | 74% |
| 12 | 2 | 44% |
| 15 | 3 | 64% |
| 20 | 5 | 53% |
| 30 | 9 | 57% |
| 40 | 13 | 52% |
| 50 | 17 | 50% |
| 60 | 21 | 48% |

### 알려진 한계

- **12명 이하는 좀비 수만으로 50:50을 맞출 수 없다.** 좀비 1명 차이로 승률이 크게 뛴다(10명: 1명 8%, 2명 74%).
- 인원이 홀수면 매 라운드 한 명이 남아 미접촉 좀비가 되므로 좀비에게 유리하다.
- 실제 플레이에서 터치 횟수가 가정(라운드당 1회)과 다르면 승률이 크게 달라진다. 터치가 많을수록 좀비가 유리하다.

## 6. 다음 작업 후보 (미확정)

1. 실제 행사에서 한 번 진행해 보고, 실제 터치 횟수 분포를 바탕으로 `WIN_RATE` 가정 재검토.
2. 소규모(12명 이하)용 밸런스 보정 방법 검토 — 좀비 수 외의 수단(예: 치료제 시간, 미접촉 규칙 완화)이 필요하다. 규칙 변경이므로 진행자 판단 필요.
3. 태블릿 세로 화면에서 4열 카드 가독성 확인.
4. 결과 화면 기록 내보내기(텍스트 복사 등) — 요청이 있을 때만.
